# Atari File Forge 0.4.0

A driver's boot loaders are now kept once they have been copied, so a drive
prepared with AHDI or ICD Pro boots on a machine running its original TOS ROM
without another drive having to be open.

0.3.0 made that possible by copying both loaders from a drive the driver had
already prepared, but only from a drive open in the other pane, every time.
The loaders are the same on every drive a driver prepares, so there is no
reason to keep asking for one.

## The boot loaders folder

When the Prepare dialog copies loaders from an open drive, it keeps a copy,
unless you untick **Keep a copy**, in `~/.config/atari-file-forge/bootloaders`,
or the directory named by `ATARI_FILE_FORGE_BOOTLOADER_DIR`. `firmware/bootloaders`
beside the source is read as well. Each driver release gets a folder of its own:

| File | Holds |
| --- | --- |
| `ROOTLOAD.BIN` | The root sector's loader, with the partition table below it cleared |
| `BOOTLOAD.BIN` | The boot sector's loader, with its serial number and parameter block cleared |
| `SOURCE.TXT` | Which drive the pair was saved from, and which file it loads |

From then on, preparing any drive with that driver writes the saved loaders,
the driver's description in the dialog says they are saved, and the drive
keeps its own partition table and parameter block as before. A drive chosen
under **Boot loader** still takes precedence over a saved pair.

Which driver a pair belongs to is read from the file its boot sector loads,
`ICDBOOT.SYS` or `SHDRIVER.SYS`, not from the folder's name, so a pair saved
for one driver is never used for another. The loaders are the driver's own
code: the folder is ignored by Git like the drivers are, and nothing in it is
shipped.

Loaders saved from a real ICD Pro 6.55A drive and a real AHDI 6.06 drive were
used to prepare two fresh drives with nothing else open. Both boot in Hatari
as a Mega ST on genuine TOS 1.04. The AHDI pair was saved from a drive on an
IDE adapter and loads the driver over ACSI just the same.

## AHDI's loader on an ICD drive

AHDI's root loader is longer than ICD's. It runs over the bytes where an ICD
partition table keeps its eight extra entries, so on a drive partitioned for
ICD it could only be written cut short, and a truncated loader crashes the
machine at boot. That is now refused, with the reason, before anything is
written.

## Known restrictions

The [product handbook](../../README.md#known-limits-of-this-release) lists the
known limits. The first drive prepared with a driver still needs a drive that
driver prepared, or its own installer. The real-hardware gate has not been
recorded for this release; keep a known-good copy of anything you put onto a
real machine.

## Validation

The Python, JavaScript and browser suites and the AMD64, ARM64 and ARMv7 image
builds run on every commit. The release workflow builds and inspects the six
packages attached to this release before publishing it: EmuTOS present, no TOS
ROM, and the bundled HxCFloppyEmulator converter running. The
[release checklist](../RELEASE-CHECKLIST.md) defines the full gate.
