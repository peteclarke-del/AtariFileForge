# Atari File Forge 0.2.0

The native package now carries the bundled EmuTOS, which 0.1.0 left out, so the
emulator starts on any machine without a TOS ROM of your own. This release also
adds presets for five machines as they are commonly kept today, and lets a
Falcon030 profile ask for TOS 4.00, 4.02 or 4.04 by name.

Upgrade if you installed a 0.1.0 package. Without a TOS ROM of your own in
`~/.config/atari-file-forge/tos`, its emulator reported every machine as
unavailable. The Docker image was not affected.

## EmuTOS in the package

The 0.1.0 packages copied nothing from `firmware/`, a rule carried over from
the port that does not fit this project: EmuTOS is GPL, committed under
`firmware/emutos`, and is what boots a machine when no TOS ROM has been
supplied. Asked to start a Mega ST with no ROM, an installed 0.1.0 answered "No
ROM for the MEGAST was found, and the bundled EmuTOS is missing".

The package now carries `firmware/emutos` and nothing else from `firmware/`,
since the rest of that folder is where you keep ROMs, drivers and desktops that
are yours alone. Before a release is published, every package is opened and
checked: EmuTOS and its licence are present, no TOS ROM is, the
bundled HxCFloppyEmulator converter runs, and the packaged application, given
no ROM, chooses EmuTOS for a Mega ST.

Genuine TOS is never shipped and cannot be. An installed package looks for
your own ROMs in `~/.config/atari-file-forge/tos` and your hard-disk drivers in
`~/.config/atari-file-forge/drivers`. If you keep them in a checkout's
`firmware/` folder, link those two folders to it and the application uses them
from there.

## New presets

| Preset | Machine | TOS | RAM | Storage |
| --- | --- | --- | --- | --- |
| 1040 STF · 1 MiB, ACSI2STM and a Gotek | ST | 1.04 | 1 MiB | ACSI2STM, Gotek |
| 1040 STE · 4 MiB and ACSI2STM | STE | 1.62 | 4 MiB | ACSI2STM |
| Mega ST · 4 MiB, blitter and BlueSCSI | Mega ST | 1.04 | 4 MiB | BlueSCSI through an ACSI host adapter |
| 1040 STFM · 1 MiB and ACSI2STM | ST | 1.04 | 1 MiB | ACSI2STM |
| 520 STFM · 1 MiB and ACSI2STM | ST | 1.04 | 1 MiB | ACSI2STM |

All five use the ICD Pro driver, which drives both ACSI2STM and a BlueSCSI
behind an ICD host adapter. The Mega ST's blitter is built in, so it needs no
add-on and the emulator switches it on by itself.

Saved profiles move to schema 8 on first use. A saved list gains only the
presets it does not already hold by name, added after everything else, so
nothing you saved or edited moves or changes and the profile you had selected
stays selected. A profile you saved yourself under one of the new names is left
as it is.

## Choosing a Falcon TOS

A Falcon030 profile could ask only for "TOS 4.0x", which always took the newest
ROM found. TOS 4.00, 4.02 and 4.04 are now choices of their own, and "TOS 4.0x,
newest found" keeps its old behaviour for existing profiles. A file that does
not decode as a ROM, such as a truncated or bad dump, is still never offered.

## Release engineering

- The release workflow pulls each package's build image as a step of its own
  and retries it, so a Docker Hub hiccup cannot fail a release. One held up
  0.1.0 until the job was run again.
- A test keeps the package check script free of apostrophes. One in a comment
  ended its shell quoting and failed every package build without explanation.

## Known restrictions

The [product handbook](../../README.md#known-limits-of-this-release) lists the
known limits, which are unchanged from 0.1.0. The real-hardware gate has not
been recorded for this release; keep a known-good copy of anything you put onto
a real machine.

## Validation

The Python, JavaScript and browser suites and the AMD64, ARM64 and ARMv7 image
builds run on every commit, and the release workflow built and inspected the
six packages attached to this release, EmuTOS check included, before
publishing it. The [release checklist](../RELEASE-CHECKLIST.md) defines the
full gate.
