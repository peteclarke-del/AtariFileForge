# Atari File Forge 0.5.0

The About box can now check for a newer release and, in a package installed
from a release, install it. An MSA with one track record more than its header
declares now opens instead of being refused.

## Check for Application Updates

**About Atari File Forge**, in the **Help** menu, has a **Check for
Application Updates** button. Nothing is sent until it is pressed. It asks
GitHub for the latest release, compares its version with the running one and
says either that this is the newest version, which newer version is available,
or why the check could not be made. Drafts and prereleases are never offered.

A package installed from a release then offers **Update to** the new version.
It downloads the package built for the same distribution and architecture to
`~/.cache/atari-file-forge/updates`, checks it against the release's
`SHA256SUMS`, and installs it with `pkexec apt-get install` once the system has
asked for your password. **Restart Atari File Forge** starts the new version.
Working images, preferences, profiles and the collection are kept. Nothing is
installed, and the application does not restart, while a floppy disk is being
read or written through a Greaseweazle or a floppy controller.

Each release package records the system it was built for in
`/opt/atari-file-forge/package-target`, and the release workflow checks that
record against the published file name before publishing. The Docker service
and a source checkout have no record and cannot update themselves; the button
opens the release page for them instead.
[Installation](../INSTALLATION.md#check-for-application-updates) has the
details.

## MSA archives with an extra track record

Some archivers wrote one more track record after the tracks an MSA header
declares. 3 of 12 Vectronix images sampled from the Internet Archive's
Vectronix CD carry one, and with that record left out their sectors match the
TOSEC dumps of the same disks exactly. Those images were refused. They now
open: the bytes after the last declared track are left out of the disk, and
the container project view and a converted image report how many there were.
An MSA written back from such a file is shorter than the original by that
count. Cut-off tracks, over-long tracks and bad headers are still refused.

## Upgrading

0.4.0 and earlier have no update button. Install the 0.5.0 package for your
system over the old one with APT, as the
[installation guide](../INSTALLATION.md) describes. Later releases can then be
installed from the About box.

## Known restrictions

The [product handbook](../../README.md#known-limits-of-this-release) lists the
known limits. The real-hardware gate has not been recorded for this release;
keep a known-good copy of anything you put onto a real machine.

## Validation

The Python, JavaScript and browser suites and the AMD64, ARM64 and ARMv7 image
builds run on every commit. The release workflow builds and inspects the six
packages attached to this release before publishing it: EmuTOS present, no TOS
ROM, the bundled HxCFloppyEmulator converter running, and the recorded package
system matching the published file name. The
[release checklist](../RELEASE-CHECKLIST.md) defines the full gate.
