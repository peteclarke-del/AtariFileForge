# Atari File Forge 0.6.0

The Linux desktop application now treats a real floppy disk as a source in the
same way as an image file. A disk in a Greaseweazle drive, or in a drive on
the host's own floppy controller, can be read straight into a pane. The
geometry is taken from the disk's own boot sector.

## Read a floppy disk

**Read floppy disk** appears on an empty pane and as **File → Read floppy
disk…** in an open one. The dialog lists every Greaseweazle drive and every
floppy controller the host exposes. Choose what to capture:

- an ST or MSA sector image to edit, run in an emulator or put on a Gotek
- SCP or HFE flux to archive a damaged or copy-protected disk

The disk is only read. The capture goes to a private temporary file and opens
in the pane only once the read has finished cleanly, so a failed read or an
empty drive never becomes a pane you might trust. **Abort operation** stops
the drive and opens nothing.

A sector capture first reads only cylinder 0, side 0, which holds the boot
sector, and takes the disk's tracks, sides and sectors from its BIOS parameter
block. A high-density disk is probed again at its own data rate. A disk
without a usable boot sector is refused with a request to choose the geometry,
or to capture flux, rather than being read at a guessed shape. The same
detection applies to a floppy controller.

IPF is no longer offered as a capture format, because Greaseweazle can read
IPF but has no writer for it.

## Write a floppy disk

**Write physical floppy…** now lists any floppy controller alongside the
Greaseweazle drives as the destination for a plain `.st` image. A controller
does not read the disk back, so the dialog says the write is unverified. The
dialog no longer shows capture fields that a write never used.

## HDDRIVER from its distribution floppy

The HDDRIVER distribution floppy carries its driver as `AUTO\HDDRIVER.PRG`.
That name is now recognised when the floppy, an image of it or a folder copied
from it is supplied as a driver, and the file is installed as `HDDRIVER.SYS`,
which is what HDDRIVER's loader reads. As with every driver, the boot loaders
for a genuine TOS ROM come from a drive that HDDRUTIL has prepared. The
[firmware guide](../../firmware/README.md#hard-disk-boot-loaders) explains how
they are saved.

## Upgrading

Install the 0.6.0 package for your system from the About box's **Check for
Application Updates**, or with APT as the
[installation guide](../INSTALLATION.md) describes. Working images,
preferences, profiles and the collection are kept.

## Known restrictions

Reading and writing real disks needs the native Linux application. The browser
and Docker editions cannot reach host USB hardware. Greaseweazle has no
definition for 81 to 83 tracks, so such disks are captured as SCP or HFE flux.
The [product handbook](../../README.md#known-limits-of-this-release) lists the
other known limits. The real-hardware gate has not been recorded for this
release. Keep a known-good copy of anything you put onto a real machine.

## Validation

The Python, JavaScript and browser suites and the AMD64, ARM64 and ARMv7 image
builds run on every commit. The release workflow builds and inspects the six
packages attached to this release before publishing it: EmuTOS present, no TOS
ROM, the bundled HxCFloppyEmulator converter running, and the recorded package
system matching the published file name. The new read path was also exercised against a
Greaseweazle F1: a 720K disk was detected from its boot sector, captured, and
opened byte-identical to a separately made image of the same disk. The
[release checklist](../RELEASE-CHECKLIST.md) defines the full gate.
